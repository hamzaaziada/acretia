## Report and pipeline structure (file:line, `finrobot_desktop/finrobot/engine/`)

- [OBSERVATION] Pipeline steps: `create_equity_research_pipeline` (`pipelines/equity_research.py:1582`) defines eight `PipelineStep`s: `data_collection` (critical, `:1590,1617`), `catalyst_analysis` (`:1620`), `peer_analysis` (`:1637`), `financial_modeling` (deterministic, `:1648,1655`), `ownership_governance_analysis` (`:1666,1676`), `technical_analysis` (`:1679,1689`), `thesis` (`:1692`, structured validator) and `report` (`:1703`, text validator).
- [OBSERVATION] Step contract (`pipelines/step.py:32-80`): each `PipelineStep` has an agent, a validator, an executor, `required_data`, a `deterministic` flag (a pure function of structured context that must not be retried by re-prompting, because a retry would reproduce the same failing output) and a `critical` flag (failure aborts the run with `PipelineStepError`; otherwise the run degrades and records `failed_validations`).
- [OBSERVATION] Runner: `Pipeline` with `max_retries = 3` (`pipelines/runner.py:443`), validation-retry loop (`:791-860`), degrade-not-die contract for non-critical steps (`:78-81,553-618`), failed validations collected as `{"step", "error"}` entries (`:493,595`).
- [OBSERVATION] Deterministic maths is separated from narrative: DCF, LBO, DDM, comps and residual income live in `compute/operators/*.py` and run as executors with `deterministic=True`; LLM agents write the thesis and report on top of the structured context. Validators range-check outputs (peer multiple sanity bands, DCF result checks) in `pipelines/validators.py:289,425,498`.
- [OBSERVATION] Narrative audits: `compute/operators/audit/narrative_numeric_grounding.py:54` flags thesis fields (`narrative`, each `catalysts[i]`, each `risks[i]`) that carry no digit after stripping years and ordinals. My offline run on a synthetic thesis returned `[NARRATIVE-NUMERIC] 2 narrative field(s) carry no supporting number (catalysts[0], risks[0]) ...` while the bullet "Buyback of $90bn" and the narrative with "14% to $109bn" passed. The check only tests for any digit, so it does not tie a number to a source. Sibling audits: `narrative_divergence.py`, `ttm_period.py`, `currency_caliber.py`, `ev_bridge.py`, `sector_sign.py`.
- [OBSERVATION] Judge prompt (`agents/instructions/judge_agent.md`): bull and bear agents argue, a judge issues BUY/HOLD/SELL with conviction, "swing_factor" and "change_my_mind"; "The judge does not cite specific numbers" and must always call a direction. This is investment-opinion output, which Acretia does not produce.
- [OBSERVATION] Data: `edgar_provider.py` pulls SEC filings (10-K/10-Q/8-K/XBRL); a note in `equity_research.py` explains that a single 10-K triples through items, sections and `mdna_text` and pushed a META prompt to 146,840 tokens above a 128k limit, which is why the executor fetches filings outside the prompt (comment at `equity_research.py:1590-1616`).
- [INFERENCE] The valuable ideas for S6.1/S6.2: (1) the `deterministic` and `critical` step flags and degrade-with-markers semantics; (2) separating numeric compute from narrative; (3) numeric-grounding audits as non-blocking gates; (4) range-validators on structured outputs. All four fit the harness router and "reject any figure without a verifiable source and as-of date".
- [INFERENCE] What does not fit: free-text investment theses with price targets, bull/bear debate and judge, and any recommendation output. The grounding audit is weaker than Acretia's requirement (it accepts any digit, not a cited fact).

## Adopt / borrow ideas / isolated service / skip for Acretia

Borrow ideas: the pipeline step contract (validators, `deterministic`, `critical`, degrade markers), compute-versus-narrative separation, and the audit-function pattern. Do not adopt the package: its product is analyst-style opinion reports with trademark-restricted branding, and the narrative layer would be replaced by SlideSpec/Excel-payload emission with source and as-of fields.
