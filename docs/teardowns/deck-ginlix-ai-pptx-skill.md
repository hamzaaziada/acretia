## Findings

- [OBSERVATION] It is a skill, not an engine: SKILL.md (322 lines) tells the agent to write a pptxgenjs build script, run check.py on the saved file, render to PNG with render.py and fix in the script (SKILL.md "Workflow"). Three scripts: check.py (1,101 lines), extract.py (499), render.py (327).
- [OBSERVATION] Layout method is absolute coordinates from one geometry function per deck: 16:9, 0.6 in margins, title y 0.45 h 0.60, kicker 1.05, rule 1.42, content from 1.75, footer 6.95 (SKILL.md "Geometry"). Type scale: cover 40, title 28, heading 18, body 16-18, table 14, chart labels 12, footer 10 pt; two font families at most; fonts restricted to metric-safe families with clones installed (SKILL.md "Type", "Fonts").
- [OBSERVATION] check.py audits the saved .pptx whoever built it: package integrity, bounds, overlap and occlusion (including inside groups, rotation and flips), text overflow estimate (0.50 em glyph, 0.54 bold, 1.2 line height), placeholders such as Lorem/TODO, font floors (body 10 pt, table 14 pt), at most two fonts, title drift between slides, notes presence, charts as pictures (check.py:1-60, 727-997). Output is JSON with level fail/warn/info, counts and examples naming slide and shape.
- [OBSERVATION] On the 19 decks produced here it ran without error and discriminated well: om a: 0 fail; swak b: 113 fail instances; text-on-shape overlap produces many "overlap" fails for deliberately layered designs (hand-drawn bars with labels), so occlusion logic needs a "contained text is fine" rule.
- [OBSERVATION] Charts must be native: "Charts stay native. addChart writes a real chart part" with a bar example (SKILL.md "Build a New Deck"); the page number must be a 10 pt text box, not slide.slideNumber (SKILL.md "Budgets check.py holds you to").
- [OBSERVATION] Colour roles are specified as a fixed palette (ink 1A1A1A, secondary 5A5A5A, rule D8D5D0, panel F4F2EE, accent 1F4E79, series 4E86B8/8FB4D4, gain 1A7F4F, loss B42318) with "green and red mean gain and loss and nothing else" (SKILL.md "Colour").
- [OBSERVATION] No RTL guidance in SKILL.md or the scripts.
- [INFERENCE] The audit-the-file-not-the-script principle and the JSON finding schema are directly usable for validate_pptx.py (S3.7). check.py works on any producer's output, which also makes it a good neutral benchmark for the S3.10 eval.
- [UNKNOWN] Whether check.py's overflow estimate correlates with LibreOffice renders: only spot-checked by eye; text_tight warnings were frequent and not verified one by one.

## Adopt / borrow ideas / skip

Borrow ideas and design the validator in the same spirit (Apache-2.0 would allow reuse with attribution): geometry-from-saved-XML including layout-inherited placeholders, group/rotation handling, fail/warn/info levels, --strict exit code, one-line findings with slide and shape. Skip the pptxgenjs build path as the primary renderer.
