# Decisions

Newest last. Each entry gives the choice and why. Agents add entries here instead of asking the user.

- **D-001 (2026-11-16) Keep the standard-library core.** The engine stays pure Python 3.10+ with no pip dependencies, and it is the "native offline CI" runtime: SQLite WAL, our own xlsx/pptx writers and our own formula evaluator. Optional packages are added only behind feature flags (pdfplumber, pypdfium2, duckdb, and openpyxl for **independent verification only**), and a missing one degrades gracefully. *Why:* zero-dependency runs are what make the offline gates deterministic, and the existing 144 tests rely on this.
- **D-002 (2026-11-16) Web layer.** The existing hardened stdlib HTTP server (Host and Origin guard, security headers) stays the API, and the static HTML UI stays the frontend for v1. The master prompt names FastAPI and Next.js: they are not adopted now, because they would mean rewriting a working, tested surface for no user-visible gain before M6. Revisit after M7 if multi-instance scaling needs it.
- **D-003 (2026-11-16) Storage in deployment.** SQLite in WAL mode remains the system of record, single node (search relies on FTS5). Postgres, Redis and MinIO are optional compose profiles behind adapters (`om/storage.py`): blobs can go to S3-compatible storage, and the job queue to Redis. DuckDB is used for document grids when installed.
- **D-004 (2026-11-16) LLM routing.** Every runtime AI call goes through `om/llm.py` Router. Default provider: the MeshPool gateway at `https://llm.meshpool.ai/v1`. Its key lives only in the macOS Keychain or the owner-only secrets file, and is bound to that host. CI uses replay fixtures and never makes a live call.
- **D-005 (2026-11-16) Models are written by code.** Formulas and historical numbers are written by deterministic builders. The LLM only proposes assumptions and prose. Every delivered workbook passes `om.modelcheck` critical graders, and its evaluator values match LibreOffice where available.
- **D-006 (2026-11-16) LibreOffice is a verifier, not the solver.** Its iterative solver doesn't converge on interest circularity, so circular models are verified with circularity off in LibreOffice and with `om.formula` when it is on. Headless LibreOffice needs a writable profile (`-env:UserInstallation`), and on the author's Mac it must run outside the Claude Code sandbox.
- **D-007 (2026-11-16) Notifications.** The master prompt asks for WhatsApp or OpenClaw. Neither is configured here, so milestone notifications use the Claude Code `PushNotification` tool, which reaches the phone through Remote Control. An app-level webhook (`OM_NOTIFY_WEBHOOK`) can be added in M7 for job-completion alerts.
- **D-008 (2026-11-16) Roles.** "Opus Boss / Sonnet Executor" maps to: the main Claude Code session (Opus) plans, writes the gate scripts and verifies; executor packets run as subagents on Sonnet; one packet per subagent; receipts in the agreed format.
- **D-009 (2026-11-16) Authentication.** The user earlier asked for no login while running locally. The production deploy needs auth and tenancy (M6, P6.1). Local single-user mode stays available only when the server binds to localhost.
- **D-010 (2026-11-16) Repository contents.** `data/`, `.env`, `.claude/` and caches are never committed. They hold personal decks, data rooms, SEC caches and settings. API keys are never in the repo.
- **D-011 (2026-11-16) Queue payloads are bytes/str.** `SQLiteKV`/`RedisKV` queues store opaque bytes; callers JSON-encode. Keeps Redis and SQLite semantics identical.
- **D-012 (2026-11-16) S3 path-style addressing.** `S3BlobStore` uses `/bucket/key`, which MinIO and AWS both accept; credentials only from args or `ACRETIA_S3_*`.
- **D-013 (2026-11-16) LLM mode default.** `ACRETIA_LLM_MODE` defaults to `live` in the app so existing fake-provider tests keep working; CI and every gate set `replay`, and replay never constructs a provider. PII masking is on by default; fixtures are keyed on the masked prompt so they never contain PII.
- **D-014 (2026-11-16) NINO masking follows HMRC prefix rules.** Reserved prefixes (e.g. the `QQ` specimen) are not treated as real identifiers; card numbers need a Luhn pass and IBANs a mod-97 pass, so ordinary financial figures are never masked.
- **D-015 (2026-11-16) MeshPool default model id is `auto`** until the gateway's model list is known; the key is bound to `llm.meshpool.ai` (https, port 443, exact host) and redirects off-host are refused while a key is attached.
- **D-016 (2026-11-16) Branch policy.** Work is committed on the session branch `claude/dreamy-ramanujan-k8p2xt`; each gate-passed milestone is also pushed to `main` as the user asked. Pre-gate work is pushed only to the session branch.

## v2 pivot (2026-11-16)

- **D-017 Plan v2 replaces M1–M7.** The user's architectural pivot makes four things the organising principles: a licence ledger, a model-agnostic adapter, a Harness/MCP router and four workstreams with buyer-persona gates. v1 packets map into v2 stages (PLAN.md §2), and v1 M1 is complete and gated (om/contracts.py, om/storage.py, om/pii.py, om/replay.py, om/deals.py, verify_m1 19/19); Stage 2 builds on it.
- **D-018 D-001 relaxed: vetted dependencies are allowed.** Permissive packages (MIT, Apache-2.0, BSD, MPL-2.0) may be core dependencies once they have a ledger row: python-pptx, fonttools, Pillow, arabic-reshaper, python-bidi, duckdb, docling, edgartools, FinanceToolkit, crawl4ai, gpt-researcher components. They are pinned in `pyproject.toml`. The existing standard-library modules keep working and stay the offline fallback where cheap (xlsx writer, formula evaluator, pptx writer). GPL/AGPL code (Marker, MinerU, and any OpenBB module under AGPL) runs only as an isolated Docker service.
- **D-019 Package layout.** New harness code goes in `src/harness/` (as the pivot specifies). The engine package stays at `om/` to avoid churn; `pyproject.toml` exposes both, and `om` imports nothing from `src/harness` except through the adapter and contracts.
- **D-020 Two kinds of LLM use.** (a) *Runtime product calls*, such as extraction, specs and the vision critic, go only through `src/harness/adapter.py`, to any OpenAI-compatible endpoint; the MeshPool gateway is the default. (b) *Build-time agents* (Boss, Sonnet workers, Haiku buyer personas) are Claude Code subagents. They are not part of the product and never ship in it.
- **D-021 Live evals need keys the cloud session doesn't have.** S3.10 (20 briefs × 2 frontier + 1 open-weight model) and S6.3 (Vals / FinanceBench) need a model endpoint. Build the harnesses and run them in replay/offline mode in CI. Run them live when the user supplies an endpoint, either as a cloud environment secret or locally with the Keychain-held MeshPool key, and record which ran live in `scorecard.csv`. Never fake a live result.
- **D-022 Prior internal code.** `reference/meshpool-harness/` is a curated, secret-scanned copy of the user's MIT "Meshpool Harness Experiment": router, profiles, ledger, slides/sheets engines. Port from it into `src/harness/` and the deck engine. Ledger row: `internal/meshpool-harness, n/a, MIT, adopt`.
- **D-023 UI stays server-rendered for now.** The pivot allows "frontend/ or server pages". The split-pane inspector, matrix grid and workbench are built as pages served by the existing hardened server, using pdf.js (Apache-2.0, vendored, pinned). Reconsider a separate `frontend/` app only if the persona gate scores the UI below 8.5 for reasons a page app can't fix.
- **D-024 Crawling.** crawl4ai is used only for public IR pages and press releases. It honours robots.txt, is rate-limited and identifies itself, and stores facts plus links, never republished articles.

- **D-025 (2026-11-16) Generative visuals, deterministic polish (user direction).** Decks must not have a rubber-stamp feel. The creative layer (art direction, visual concepts, illustrations, hero images, diagram styles) is generative and non-deterministic: several candidates are made and the critics pick the best, with scores logged so styles improve over time (PLAN S3.11). Polish stays deterministic: grid, metrics, contrast, overflow, data-bound native charts. The image model is used whenever its endpoint works. On 2026-11-16 the MeshPool `/v1/images/generations` path still returned `gateway_path_not_exposed`, so the SVG designer (text model draws SVG) is the live fallback. The engine probes for the image model on every run. Excel output gets the same polish bar (PLAN S4.7).
- **D-026 (2026-11-16) Parallel cloud sessions.** S3, S4 and S5 each run in their own cloud session while session A does S1 → S2 → S6 → S7 (PLAN §2b). Lock claims are pushed to `main` immediately; decisions use per-session ids.
