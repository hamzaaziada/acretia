# Decisions

Newest last. Each entry gives the choice and why. Agents add entries here instead of asking the user.

- **D-001 (2026-11-16) Keep the standard-library core.** The engine stays pure Python 3.10+ with no pip dependencies, and it is the "native offline CI" runtime: SQLite WAL, our own xlsx/pptx writers and our own formula evaluator. Optional packages are added only behind feature flags (pdfplumber, pypdfium2, duckdb, and openpyxl for **independent verification only**), and a missing one degrades gracefully. *Why:* zero-dependency runs are what make the offline gates deterministic, and the existing 144 tests rely on this.
- **D-002 (2026-11-16) Web layer.** The existing hardened stdlib HTTP server (Host and Origin guard, security headers) stays the API, and the static HTML UI stays the frontend for v1. The master prompt names FastAPI and Next.js: they are not adopted now, because they would mean rewriting a working, tested surface for no user-visible gain before M6. Revisit after M7 if multi-instance scaling needs it.
- **D-003 (2026-11-16) Storage in deployment.** SQLite in WAL mode remains the system of record, single node (search relies on FTS5). Postgres, Redis and MinIO are optional compose profiles behind adapters (`om/storage.py`): blobs can go to S3-compatible storage, and the job queue to Redis. DuckDB is used for document grids when installed.
- **D-004 (2026-11-16) LLM routing.** Every runtime AI call goes through `om/llm.py` Router. Default provider: the MeshPool gateway at `https://llm.meshpool.ai/v1`. Its key lives only in the macOS Keychain or the owner-only secrets file, and is bound to that host. CI uses replay fixtures and never makes a live call.
- **D-005 (2026-11-16) Models are written by code.** Formulas and historical numbers are written by deterministic builders. The LLM only proposes assumptions and prose. Every delivered workbook passes `om.modelcheck` critical graders, and its evaluator values match LibreOffice where available.
- **D-006 (2026-11-16) LibreOffice is a verifier, not the solver.** Its iterative solver doesn't converge on interest circularity, so circular models are verified with circularity off in LibreOffice and with `om.formula` when it is on. Headless LibreOffice needs a writable profile (`-env:UserInstallation`), and on the author's Mac it must run outside the Claude Code sandbox.
- **D-007 (2026-11-16) Notifications.** The master prompt asks for WhatsApp or OpenClaw. Neither is configured here, so milestone notifications use the Claude Code `PushNotification` tool, which reaches the phone through Remote Control. An app-level webhook (`OM_NOTIFY_WEBHOOK`) can be added in M7 for job-completion alerts.
- **D-008 (2026-11-16) Roles.** "Opus Boss / Sonnet Executor" maps to: the main Claude Code session (Opus) plans, writes the gate scripts and verifies; executor packets run as subagents on Sonnet; one packet per subagent; receipts in the agreed format.
- **D-009 (2026-11-16) Authentication.** The user earlier asked for no login while running locally. The production deploy needs auth and tenancy (M6, P6.1). Local single-user mode stays available only when the server binds to localhost.
- **D-010 (2026-11-16) Repository contents.** `data/`, `.env`, `.claude/` and caches are never committed. They hold personal decks, data rooms, SEC caches and settings. API keys are never in the repo.
- **D-011 (2026-11-16) Queue payloads are bytes/str.** `SQLiteKV`/`RedisKV` queues store opaque bytes; callers JSON-encode. Keeps Redis and SQLite semantics identical.
- **D-012 (2026-11-16) S3 path-style addressing.** `S3BlobStore` uses `/bucket/key`, which MinIO and AWS both accept; credentials only from args or `ACRETIA_S3_*`.
- **D-013 (2026-11-16) LLM mode default.** `ACRETIA_LLM_MODE` defaults to `live` in the app so existing fake-provider tests keep working; CI and every gate set `replay`, and replay never constructs a provider. PII masking is on by default; fixtures are keyed on the masked prompt so they never contain PII.
- **D-014 (2026-11-16) NINO masking follows HMRC prefix rules.** Reserved prefixes (e.g. the `QQ` specimen) are not treated as real identifiers; card numbers need a Luhn pass and IBANs a mod-97 pass, so ordinary financial figures are never masked.
- **D-015 (2026-11-16) MeshPool default model id is `auto`** until the gateway's model list is known; the key is bound to `llm.meshpool.ai` (https, port 443, exact host) and redirects off-host are refused while a key is attached.
- **D-016 (2026-11-16) Branch policy.** Work is committed on the session branch `claude/dreamy-ramanujan-k8p2xt`; each gate-passed milestone is also pushed to `main` as the user asked. Pre-gate work is pushed only to the session branch.

## S5 document grid (session D)

- **D-S5-01 (2026-11-16) Parser.** docling (MIT; layout weights Apache-2.0, TableFormer weights CDLA-Permissive-2.0, pinned in the ledger) is the default layout backend (`ACRETIA_PARSER=auto`). om.pdfdoc word geometry is always loaded as well, and every citation bbox comes from it through `om.docparse.locate`, never from layout-block boxes. A docling failure falls back to pdfdoc with a warning. Marker and MinerU are reachable only as isolated HTTP services (`ACRETIA_MARKER_URL`, `ACRETIA_MINERU_URL`). docling costs about 6.5 s per page on CPU, so parsed documents are cached by sha256.
- **D-S5-02 (2026-11-16) Completeness.** A page is complete when the multiset recall of its pdftotext tokens in the backend's block text is at least 0.97 (`ACRETIA_COMPLETENESS_MIN`). Tokens are NFKC-normalised, casefolded, with punctuation and symbols stripped. Below the threshold, the missing text-layer lines are added back as `recovered` blocks. The warning and the pre-recovery value are kept. Evidence: docling dropped 84–100% of the tokens on the iXBRL cover pages of a real Apple 10-K, and all were recovered (`docs/s5/parser-docling.md`).
- **D-S5-03 (2026-11-16) VDR risk detector is deterministic.** Clause findings work sentence by sentence and need operative language. Negation before a keyword suppresses a finding, except that "shall not" stays operative in covenants. Glossary definitions are ignored. Period coverage is read only from statement and management-account documents (the name plus the start of page 1), so prior-year comparatives don't count. Conflict severity is inherited from `om.consistency.find_conflicts`. A finding whose locator fails keeps `bbox_norm=None` and `locate_failed`, and never gets an invented bbox.
- **D-S5-04 (2026-11-16) Roles follow D-027.** The S5 Boss wrote the gate spec, and `scripts/verify_s5.py` is written by a separate Sonnet worker who does not see the implementers' tests.
- **D-030 (2026-11-16) IFRS first; anchor companies (user direction).** S8 builds IFRS depth first, then EAS, SOCPA and UAE variants. Nine listed non-financial companies serve as understanding tests, using both audited statements and earnings releases: SWDY, EAST and TMGH (Egypt); Almarai, Jarir and SABIC (KSA); Emaar, ADNOC Distribution and Aldar (UAE). The third group of "two or three publicly listed companies" was read as UAE/GCC; if the user meant another market, add it.
- **D-031 (2026-11-16) Reviews follow events.** The independent reviewer runs whenever a stage gate, packet merge or PROGRESS change lands on `main` (debounced to at most one review per 30 min), with a 6-hourly heartbeat for stall detection. This replaces the 2-hourly cadence.
## Session F: product app (Felix parity)

- **D-SF-01 (2026-11-16) Backend stays standard-library, in a new package `om/api/`.** A versioned JSON + SSE API on `ThreadingHTTPServer` and SQLite WAL meets every D-029 requirement: multi-tenant auth with org roles, CSRF/Origin checks, hashed sessions, a hash-chained audit log, streamed job events with `Last-Event-ID` replay, and resumable jobs. A framework (FastAPI/Starlette + uvicorn) would add dependencies and a second server model without adding any of these. `om/web.py` and `om/static` stay as internal tools. Revisit if multi-instance deployment needs it (S7.5). Contract: `docs/product/SPEC.md`.
- **D-SF-02 (2026-11-16) Frontend stack.** React 18.3.1 + TypeScript 5.6 + Vite 5.4, react-router-dom 6.28, pdfjs-dist 4.10.38, self-hosted Inter / IBM Plex Sans Arabic / JetBrains Mono (OFL-1.1), @playwright/test 1.63.0 (matches the preinstalled browsers). No UI kit and no CSS framework: our own token-based design system, so the product doesn't look like a template. All have ledger rows. `frontend/dist` is a build output and isn't committed; the server serves it, and `verify_product.py` builds it.
- **D-SF-03 (2026-11-16) Session and CSRF model.** Opaque random session tokens in an `HttpOnly; SameSite=Strict` cookie, stored only as SHA-256 hashes; a per-session CSRF token sent as `X-CSRF-Token`, plus an Origin check on every unsafe method. Passwords use stdlib scrypt. *Why:* stdlib only, no JWT revocation problem, and strict same-site cookies plus a header token stop CSRF even if a future route forgets one of the two layers.
- **D-SF-04 (2026-11-16) Cross-tenant access answers 404.** A resource in another org is indistinguishable from one that doesn't exist. The tenancy test is driven by the route table, so every new route is covered automatically.
- **D-SF-05 (2026-11-16) Roles are owner / member / viewer** (as the user specified). Owners do firm setup, users, connectors, mailbox and audit; members run agents and edit; viewers read. The last owner can't be removed or demoted (409 with a hint).
- **D-SF-06 (2026-11-16) Rule-first planner.** Command-bar requests are matched to built-in agents by deterministic rules (keywords, tickers, deal entities, assumption overrides such as "9% WACC"). Only unmatched prompts go to the model through the adapter, with replay fixtures in tests. *Why:* plans for the common banker requests are instant, free and reproducible, which makes the journeys testable offline. This matches the S2.3 router's rule-first design.
- **D-SF-07 (2026-11-16) Missing engines fail loudly, per step.** When an engine stage hasn't landed on `main`, the step that needs it fails with a hint naming the stage; the rest of the plan still runs. Interim fallbacks are only the existing, verified engines (`om.studio`/`om.pptx` for decks, `om.matrix` extractive for grids, `om.ask` for research), and they are labelled as such in the step detail.
- **D-SF-08 (2026-11-16) Email-in never sends.** The org's own IMAP mailbox (or a local maildir for on-prem and tests) is polled; only senders who are org members (or are on the owner's allowlist) create jobs; everything else is rejected and audited. No SMTP code runs unless the owner enables `send_enabled`, which defaults to off. Mail bodies are data, never instructions to the system: they become the job prompt, and attachments become deal documents.
- **D-032 (2026-11-16) Goal: parity with Hebbia and Rogo on reliability, usefulness and time saved (user /goal).** Time-saved and reliability claims are earned by measurement (PLAN "North-star metrics"): a per-task human baseline vs Acretia's time to a client-ready deliverable (review/fix time included), plus reliability SLOs over at least 100 varied runs. No claim is published before it is human-validated and at or above the competitor's published claim for the same task.

## S3 deck engine (session B)

- **D-S3-01 New engine package `om/deck/` on python-pptx.** The v2 engine (spec → archetype → SolvedSlide → python-pptx renderer → validator → critic) lives in `om/deck/`; the v1 Studio path (`om/studio.py`, `om/layout.py`, `om/pptx.py`) keeps working untouched. `om/house.py` stays the single source of truth for grid, type and palette. Interfaces are in `docs/deck-engine.md`.
- **D-S3-02 DeckSpec v2 lives in `om/deck/spec.py`, not `om/contracts.py`.** Session A owns contracts; the deck spec needs archetype-specific block schemas from the registry. Geometry, font and colour keys and hex/rgb values are schema-rejected anywhere in a spec.
- **D-S3-03 No python-bidi.** Line width does not depend on visual order, so measurement uses arabic-reshaper (MIT) only; text is written to the .pptx in logical Unicode with `rtl="1"` and PowerPoint does the bidi. This avoids the LGPL dependency entirely.
- **D-S3-04 Measurement fonts.** Metric-compatible proxies: Arial→Liberation Sans, Calibri→Carlito, Cambria→Caladea/Liberation Serif, Arabic→Noto Sans Arabic (fonts-noto-core, OFL, system package, not vendored), with a 3 % width safety margin. Theme cs font is Arial (present on Mac/Windows with Arabic coverage).
- **D-S3-05 Type-size budget.** At most 4 distinct sizes per slide across text frames and tables; chart-internal text is fixed at 12 pt and does not count but must be ≥ 10 pt.
- **D-S3-06 Element ids carry the role** (`s{index}.{role}[.{suffix}]`) and become shape names, so the validator and the vision critic name shapes deterministically on any deck we render.
- **D-S3-07 Latin digits in Arabic decks** by default (Gulf banking convention); Arabic-Indic digits are opt-in.
- **D-S3-08 Offline visuals stay generative.** With no image endpoint and no key (cloud CI), the SVG designer cannot run either, so a seeded procedural generator per art direction produces the candidates; seeds are random per run, scoring and the variety rules stay deterministic. The image model is probed on every run and used whenever it answers (D-025).
- **D-S3-09 Model calls go through `src/harness/adapter.py`** (D-027, landed in S2.1): the vision critic and the integration packet use it; earlier wave-1 modules that used `om/llm.py` are switched in the integration packet.
- **D-S1-02 (2026-11-16) pyuno client import is allowed, narrowly.** `om/recalc.py` (session C) imports `uno`/`com.sun.star`, LibreOffice's MPL-2.0 Python bridge, in-process. It only talks over a socket to a separate headless `soffice` process, so the LibreOffice engine (MPL-2.0 with some GPL/LGPL components) still runs isolated. Importing an unmodified MPL-2.0 module is permitted. The S1 gate allows exactly `(om/recalc.py, uno)` and `(om/recalc.py, com)`; any other in-process import of an `isolated_service` row still fails.
- **D-033 (2026-11-16) Parity is the acceptance bar, with real graders (user direction).** Anything below Hebbia/Rogo parity in UX, UI, features, quality or speed is rejected. Every stage needs three independent graders: a deterministic gate written by a different worker, a specialist reviewer (Sonnet, with skills, judging rendered outputs), and the buyer personas. Sessions must use the best skills installed in their environment.
- **D-034 (2026-11-16) Harness lab (user direction).** A dedicated session G owns the agent runtime (S9). The design follows `docs/harness-research.md`:
  - hybrid fixed workflows with bounded agent steps;
  - the evidence ledger with `{{ev:id}}` references, so no model-written numbers;
  - a deterministic verifier ladder plus a cross-family critic;
  - single-writer artifacts;
  - cascade-on-failure routing;
  - harness evals with silent-error rate as the headline metric and CI gating.
- **D-S6-01 (2026-11-17) One scorecard schema.** `scorecard.csv` keeps the header session E created: `stage,eval,n,score,notes`. Research rows use `stage=S6`, `eval=research/<suite>/<metric>`, `score` blank unless the run is real, and `notes` carrying `mode=<replay|live>; ran_live=<yes|no>; date=<ISO>; <free text>`. A replay row never overwrites a live row. Other sessions append their own rows with the same five columns.
- **D-S6-02 (2026-11-17) Eval datasets are fetched at runtime, never vendored.** Vals v1/v2 public sets (MIT repos), FinanceBench (CC-BY-NC-4.0, local scoring only) and BankerToolBench tasks (CC-BY-4.0 with a `noai` tag: evaluation only, never training data; canary string kept intact) are downloaded into `data/evals/` with checksums in `eval/research/manifest.json`.
- **D-S1-03 (2026-11-17) Buyer house rules.** Where no authoritative source exists, `docs/buyer-research.md` sets the strictest defensible threshold, labelled `[HOUSE RULE]` (27 items). §5 there is the canonical persona rubric; PLAN §6 is a summary of it. The headline rules:
  - IB: error, BS-balance and cash-tie gates cap the score at 5.0; green cross-sheet links are required; the formula-constant allowlist is {0, 1, -1, 12, 100, 365, 1000, 0.5, 4, 52}; TV above 75% of EV is flagged.
  - MBB: 0 overlap, ≥0.25 in margins and a 12-column grid; ≤2 font families and ≤4 sizes; no archetype on more than 40% of slides; eyebrows banned and checked geometrically.
  - PE: downside ≥20% below base EBITDA; covenant headroom ≥20%; add-backs above 20% of EBITDA flagged; a 9-category risk taxonomy.
  Other sessions' deterministic validators should adopt these values or log why not.
- **D-S6-03 (2026-11-17) Figure period gate.** A cited figure's `as_of` (the date of the source's information) must be on or after the figure's period end and not in the future. Comparatives restated in a later filing are valid. A period string must resolve to exactly one fiscal period.
- **D-S6-04 (2026-11-17) Slide number check exemptions.** Every number in a research SlideSpec must match a verified figure, except ISO dates, years 1900–2100, slide/section ordinals and unitless integers 0–20 used as counts. Anything with a unit, currency, % or multiple is always checked.
- **D-S3-10 Reserved keys apply inside archetype blocks.** Data coordinates use `xv`/`yv`, option columns `a`/`b`, so the schema-level ban on geometry keys has no exceptions.
- **D-S3-11 Provenance rule.** Every figure on a slide must trace to a sourced data block (same slide or any slide in the deck), a ModelManifest value, chart series, or an archetype-declared derived value (`meta["derived"]` with its input paths). Prose and model output never count as a source.
- **D-S3-12 Accessible positive colour in the v2 deck theme.** The v1 house green #0F8A5F misses 4.5:1 with white at small sizes; `Theme.house()` uses a darker green that passes. v1 `om/house.py` is unchanged.

## S8 international accounting and OCR (session E)

- **D-S8-01 (2026-11-16) OCR engine.** tesseract 5 `ara+eng` runs as a subprocess only (ledger: isolated_service, tessdata Apache-2.0). PaddleOCR and EasyOCR are ledgered `skip`: they pull heavy runtimes, and tesseract plus a numeric re-OCR pass is measured against the G5 accuracy bar first. Revisit only if real scans miss it.
- **D-S8-02 (2026-11-16) Accuracy is measured on released figures, with coverage floors.** The tie-out and confidence gate routes uncertain figures to review, so figure accuracy is computed over released figures. Coverage, i.e. released ÷ all figures, has its own floor so that routing everything to review can't game accuracy: 90% for XBRL gold, 70% for MENA, 95% for native fixtures and 85% for scanned. The flag rate is reported separately (D-032). A wrong figure that is released without a review flag fails the gate outright.
- **D-S8-03 (2026-11-16) "Hand-verified" means agent-verified from page images, labelled as such.** No human verifier is available in the cloud session. The MENA verified subset is read off the rendered source pages by a separate Sonnet verifier that never sees the extractor's output, and each record names the verifier. The scorecard marks it "agent-verified, not human". A human pilot (PLAN North-star) replaces it when available.
- **D-S8-04 (2026-11-16) FX source.** The Central Bank of Egypt site rejects requests from the build container, so EGP month-end and average rates come from IMF IFS (`ENDE`/`ENDA`) via the DBnomics mirror, which covers 2015-01 to 2025-05. Later periods return no rate and raise `fx_rate_missing`; rates are never invented. SAR, AED and other GCC currencies use the USD pegs in `om.fx`.
- **D-S8-05 (2026-11-16) Knowledge-base confidence labels.** `verified` is reserved for facts read at a cited URL in this project (official regulator pages, or IFRS Foundation / Big-4 jurisdiction profiles). Settled IFRS and US GAAP content written from standard knowledge carries the standard reference and is reviewed by the specialist grader. Jurisdiction-specific facts not confirmed at a source stay `unverified` and are listed per entry.
- **D-S8-06 (2026-11-16) Standards QA is no longer blind.** The first run of the 50-question exam scored 26/50. Two KB fix rounds were then driven by the examiner's failure topics (content gaps, never rubric text), plus one scorer fix (percent normalisation), and the set reached 50/50. Because the fixes saw the failure topics, this set now measures coverage, not generalisation. A fresh worker writes a held-out set of 25 questions that the KB author never sees; the gate's G9.3 threshold applies to that held-out set. After the S8.1-F4 run (held-out 18/25), the Boss has seen the held-out failures, so held-out v1 is now a development set.
